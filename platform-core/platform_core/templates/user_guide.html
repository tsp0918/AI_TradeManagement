ユースケース 1: 新規品目の輸出審査フロー

Use Case 01
EAR 規制品を中国向けに初めて輸出する
半導体や通信機器など EAR 規制対象品を新規輸出する際の、品目登録から審査完了までの標準フロー。
👤 輸出管理担当者
品目登録
→
HS 判定
→
ECCN 判定
→
制裁照合
→
De Minimis
→
審査完了
1
品目を登録する ai_classification
サイドバーの 「品目管理」 を開き、「＋ 新規登録」から品目名・型番・仕様を入力して登録する。
🗂 ai_classification → 品目管理
2
HS コードを AI 判定する hs_classifier
品目詳細モーダルの 「HS コード判定」 ボタンをクリックし、AI が上位 5 候補を提示するので 適切な HS コードを選んで「反映」する。ECCN も同時に付加される。
🗂 ai_classification → 品目詳細 → HS コード判定
3
輸出取引を審査する ai_validation
「AI 該非判定」 モジュールで取引を新規登録。品名・ECCN・仕向地・需要者・用途を入力して 審査開始。7 ステップパイプライン（FAISS Layer A 照合・EAR Country Chart・Red Flag チェック等）が自動実行される。
判定結果: CLEAR / REVIEW / REQUIRES_PERMIT
🗂 ai_validation → 新規取引
4
仕向地の EAR Country Chart リスクを確認する ai_validation
取引詳細画面の仕向地欄に国コード（例: CN）を入力すると、EAR Country Chart の 該当列（AT/NP/NS 等）とリスクバッジが自動表示される。E:1 国（KP/IR/CU/SY/SD）は即時 REQUIRES_PERMIT。
🗂 ai_validation → 取引詳細 → 仕向地リスク
5
取引先を制裁リストで照合する screening
取引詳細の制裁スクリーニングセクションから照合を実行。OFAC SDN / BIS Entity List を自動照合し、 ヒットした場合は警告バナーを表示。制裁対象者との取引は法律で禁止されている。
🗂 ai_validation → 取引詳細 → 制裁スクリーニング
6
サプライチェーンを紐付けて De Minimis を確認する platform-core
取引詳細の 「🔗 サプライチェーン / De Minimis」 カードからノードを検索・選択。 仕向地を入力して De Minimis 計算を実行。US 管理品の比率が閾値（一般 25% / E:1 国 10%）を超える場合、 De Minimis ルールは適用不可となる。
🗂 ai_validation → 取引詳細 → サプライチェーン
7
許可申請ドラフトを生成する platform-core
「📋 輸出許可申請」 メニューから「⚡ 取引から生成」を選択し、取引 ID を入力すると BIS-748P（EAR）または外為法様式第1 のドラフトが自動生成される。 「フォームプレビュー」で内容を確認し、申請済みに変更後、承認番号を登録して管理する。
🗂 platform-core → 輸出許可申請
ポイント: REQUIRES_PERMIT の場合、輸出許可証を取得してから出荷すること。 DAP（先輩担当者モード）に状況を説明すると、次のアクションを具体的にガイドしてくれる。

ユースケース 2: サプライヤー原産性証明の取得と AI 検証

Use Case 02
BOM 部品のサプライヤーから原産地・ECCN 証明を取得し AI で検証する
De Minimis 計算の精度向上と原産性コンプライアンスの強化のため、部品ごとにサプライヤー申告を収集・管理する。
👤 輸出管理担当者 / 調達担当者
1
BOM ノードを登録する platform-core
「🔗 サプライチェーン管理」 から「＋ ノード登録」で品目（製品/サブアッセンブリ/部品/素材）を登録。 原産国・is_us_origin・ECCN・HSコード・価格を入力する。
🗂 platform-core → サプライチェーン管理
2
BOM ツリーを構築する platform-core
親ノードを選択してツリーを表示し、「エッジ追加」 から子ノードを検索して接続。 数量・単位を入力して BOM 構造を完成させる。
🗂 サプライチェーン管理 → ノード選択 → BOM タブ
3
招待 URL を発行してサプライヤーに送付する platform-core
証明管理タブの 「🔗 招待URL発行」 ボタンからモーダルを開き、 サプライヤー名・メール・備考・有効日数・最大送信回数を設定して URL を発行。 生成された URL（https://app.tsp-aitrademanagement.com/supplier-portal/...）を サプライヤーのメール/チャットで共有する。
🗂 サプライチェーン管理 → 証明管理タブ → 招待URL発行
4
（サプライヤー操作）ポータルにアクセスして申告する
サプライヤーは受け取った URL をブラウザで開くと申告フォームが表示される。 ECCN・原産国・米国原産コンテンツ比率・証明書参照番号を入力して送信。 送信後、受付番号が表示され、担当者側に SupplierAttestation が自動登録される。
5
AI 自動検証を実行する platform-core
証明管理タブの申告カードから 「AI 検証」 ボタンをクリック。 FAISS Layer A（外為法/ECCN 規制テキスト 2,922 件）を使って申告 ECCN と品目説明を照合し、 match / warning / mismatch / unverifiable の 4 段階で判定する。
🗂 サプライチェーン管理 → 証明管理タブ → AI 検証ボタン
6
人間が審査して承認・却下する platform-core
AI 判定結果を確認し、「承認」または「却下」を選択。コメントを記録できる。 承認済みの証明は De Minimis 計算の「証明カバレッジ」として De Minimis タブに反映される。
🗂 サプライチェーン管理 → 証明管理タブ → 承認/却下ボタン
注意: AI verdict が mismatch の場合、申告 ECCN に誤りがある可能性が高い。 サプライヤーに確認を求め、必要に応じて再申告を依頼すること。

ユースケース 3: みなし輸出審査（外国人研究者の採用）

Use Case 03
外国籍の研究者・技術者を採用する際のみなし輸出規制チェック
外為法のみなし輸出規制（外国人へのノウハウ提供が「輸出」とみなされる）に基づき、採用前にリスクを評価する。
👤 人事担当者 / R&D コンプライアンス担当者
1
R&D 案件を登録する rnd_assessment
「R&D リスク評価」 モジュールで案件（プロジェクト名・研究分野・技術カテゴリ）を新規登録。
🗂 rnd_assessment → R&D 案件管理
2
研究者・採用候補者を人物として登録する rnd_assessment
案件詳細から 「人物を登録」 ボタンをクリック。氏名・国籍・所属・専門分野を入力して登録する。 国籍が E:1 国（北朝鮮・イラン等）の場合は即座に HIGH リスク 警告が表示される。
🗂 rnd_assessment → 案件詳細 → 人物を登録
3
制裁リストで人物照合する screening
「制裁スクリーニング」 モジュールで採用候補者の氏名を照合。 OFAC SDN リストや BIS Entity List に登録されている人物との取引・提供は禁止されている。 類似名称マッチングでヒット候補が表示される場合は、本人確認書類で照合すること。
🗂 screening → 制裁リストスクリーニング
4
みなし輸出 AI 判定を実行する rnd_assessment
案件詳細のみなし輸出判定セクションで判定を実行。 研究分野と外為法規制カテゴリ（FEFTA カテゴリ）を照合し、 リスクレベル（HIGH/MEDIUM/LOW） と推奨アクション（許可申請要否・社内承認ルート）を提示する。
🗂 rnd_assessment → 案件詳細 → みなし輸出判定
5
DAP に相談して対応方針を確認する DAP
画面右下の DAP（先輩担当者モード） チャットに状況を入力。 「中国籍研究者を GaN 研究プロジェクトに参加させる場合の対応を教えてください」のように質問すると、 外為法・EAR の該当条項と対応手順を具体的に案内する。
ポイント: みなし輸出規制は外為法 25 条 1 項に基づく。技術提供（口頭・メール・デモ等）も対象。 採用後の技術アクセス範囲の管理も継続して行うこと。

ユースケース 4: 新規取引先のデューデリジェンス

Use Case 04
新規取引先（販売代理店・仕入先）の与信審査と制裁チェック
新規取引開始前に制裁対象でないことを確認し、カントリーリスクと与信スコアを評価して取引可否を判断する。
👤 営業担当者 / 経営管理部門
1
取引先を登録する platform-core
「🏢 与信管理」 から「＋ 新規登録」。会社名・国コード・役割（Customer/Supplier/Distributor 等）・ 与信スコア初期値を入力して登録する。
🗂 platform-core → 与信管理
2
制裁リスト照合を実行する screening
取引先詳細モーダルの 「照合実行」 ボタンをクリック。 screening モジュール（OFAC SDN / BIS Entity List）に照合し、結果が即座に反映される。 制裁対象の場合は overall_risk_level が自動で CRITICAL に変更される。
🗂 与信管理 → 取引先詳細 → 照合実行
3
カントリーリスクと総合リスクを確認する platform-core
詳細モーダルに表示される カントリーリスクスコア（例: CN=75 / RU=90 / KP=100）と 総合リスクレベル（LOW/MEDIUM/HIGH/CRITICAL）を確認。 算出式: (100-与信スコア)×0.4 + カントリーリスク×0.6
4
与信スコアを更新して履歴に残す platform-core
審査結果に基づいて与信スコアを更新。変更理由を記録すると 与信変更履歴 に自動保存され、 いつ誰がどのような理由でスコアを変更したかが追跡できる。
5
ダッシュボードでポートフォリオを俯瞰する platform-core
与信管理トップの 統計ダッシュボード（合計/リスク別/制裁対象数）で 全取引先ポートフォリオのリスク分布を確認。CRITICAL/HIGH の取引先を優先してフォローする。

ユースケース 5: 輸出許可申請ドラフトの作成と管理

Use Case 05
輸出許可（EAR BIS-748P / 外為法）の申請ドラフトを作成し期限を管理する
審査で REQUIRES_PERMIT となった取引について、申請書ドラフトを自動生成し、申請〜承認〜期限管理まで一元管理する。
👤 輸出管理担当者
1
取引データからドラフトを自動生成する platform-core
「📋 輸出許可申請」 メニューの 「⚡ 取引から生成」 ボタンをクリック。 ai_validation の取引 ID を入力し、申請種別（EAR / 外為法）を選択して生成。 品名・ECCN・仕向地・需要者が自動入力されたドラフトが作成される。
🗂 platform-core → 輸出許可申請 → 取引から生成
2
フォームプレビューで内容を確認する platform-core
申請詳細の 「📄 フォームプレビュー」 をクリックすると、 BIS-748P（米国商務省様式） または 外為法 様式第1 の HTML プレビューが別タブで開く。内容を確認・印刷して正式申請の下書きとして使用する。
3
申請済みステータスに変更する platform-core
実際の申請（BIS SNAP-R / 経済産業局窓口）が完了したら、詳細画面の 「申請済みに変更」 ボタンをクリックして submitted_at を記録する。
4
承認後に許可番号を登録する platform-core
許可証が交付されたら 「承認・許可番号登録」 から許可番号・発行機関・有効期限・ 許可金額を登録。ステータスが approved に変更され、期限管理が開始される。
5
期限アラートを定期確認する platform-core
輸出許可申請トップの ダッシュボード統計 で「30日以内に期限」「期限切れ」の件数を確認。 期限切れ前に更新申請を行うこと（許可証の期限切れ後の輸出は違法）。
重要: 本プラットフォームが生成するドラフトは内部確認用であり、法的効力のある正式申請書ではありません。 EAR は BIS SNAP-R システム、外為法は管轄経済産業局から正式申請してください。

ユースケース 6: 技術インテリジェンス調査

Use Case 06
競合他社の特許調査と関連学術論文から技術流出リスクを評価する
研究開発前に競合特許・学術論文を調査し、ECCN 該当技術の外部流出リスクと、採用候補者の研究実績を評価する。
👤 知財担当者 / R&D マネージャー
1
特許を検索する patent_search
「特許検索」 モジュールでキーワード・出願人・発明者名で検索。 BigQuery 未設定の場合は J-PlatPat API に自動フォールバックして検索する。 ECCN 関連特許については制裁リスト照合結果も参照できる。
🗂 patent_search → 特許検索
2
特許に関連する学術論文を確認する patent_search
特許詳細から 「関連学術論文」 タブを開くと、FAISS Layer B（特許チャンク）と Layer D（学術論文）のセマンティック検索で関連論文リストが表示される。
🗂 patent_search → 特許詳細 → 関連学術論文
3
技術インテリジェンス検索で ECCN 別トレンドを分析する rnd_assessment
「技術インテリジェンス」 画面の ECCN 別論文トレンドで、 特定 ECCN（例: 3A001=半導体、5E001=通信技術）の年次発表論文数の推移を確認。 急増している ECCN は技術流出リスクが高い可能性がある。
🗂 rnd_assessment → 技術インテリジェンス
4
採用候補者の研究実績をみなし輸出の観点でスキャンする rnd_assessment
技術インテリジェンス画面の 「みなし輸出リスクスキャン」 タブに 研究者名や研究キーワードを入力してスキャン。 ECCN 管理品に関する論文への関与度から技術保有リスクを評価する。
5
HS コードから国別規制プロファイルを確認する ai_classification
研究成果が製品化された場合の輸出先リスクを事前に把握するため、 ai_classification の 「国別規制プロファイル」 で HS コードと仕向地の組み合わせを確認。 EAR Country Chart の X 列（許可必要）や MFN 税率、貿易統計が確認できる。

FAISS Layer A（外為法/ECCN）規制テキストのセマンティック検索外為法省令 191 件・EAR/ECCN 84 件・Wassenaar 165 件・Entity List 835 件など 2,922 ベクトルを保持。クエリに対して意味的に近い規制条文をリアルタイム検索。
FAISS Layer B（特許チャンク）特許テキスト検索特許明細書をチャンク分割した 1,595 ベクトル。技術説明から類似特許群をセマンティック検索。
FAISS Layer C（HS コード）HS コードのセマンティック検索HS コード品目説明 5,476 ベクトル。品名・仕様テキストから近傍 HS コードを高速検索。日本語 FEFTA ラベルを除外して精度を確保。
FAISS Layer D（学術論文）技術インテリジェンス検索Semantic Scholar + Lens.org から収集した学術論文の要旨ベクトル。ECCN 別技術用語辞書（20 ECCN × 技術用語）で収集・タグ付けし Layer D に格納。
知識グラフ（NeuroSymbolic）規制ルールの構造化表現外為法 191 件・EAR/ECCN 84 件・Wassenaar 165 件・HS 281 件・特許 67 件のノードに、IPC→ECCN/FEFTA エッジ 996 件を追加した 788 ノードのグラフ。HanteiAgent の推論基盤。
HanteiAgent（該非判定 AI）AI 自律判定エンジン知識グラフ + FAISS を組み合わせた 7 ツール構成のエージェント。usage_expand（用途拡張）→ matrix_match（規制マトリクス照合）→ dual_list_check（二重用途チェック）→ patent_retrieve（特許照合）→ catchall_assess（汎用評価）→ export_control_evaluate（輸出規制評価）→ finalize（判定確定）の順に自律実行。
キャッチオールエンジン汎用輸出管理の決定論的判定6 ステップの決定論的ルール: E:1 国チェック → ホワイト国チェック → EAR Country Chart 照合（13 列）→ Red Flag 7 項目チェック → 総合スコアリング → REQUIRES_PERMIT / REVIEW / CLEAR 判定。
規制動向モニタリング法規制変更の自動検知e-Gov（日本）・BIS（米国）を 24 時間周期で自動クロールし、差分を RegulatoryChange テーブルに記録。ダッシュボードのアラートバナーで担当者に通知。severity（info/warning/danger）で重要度分類。
モジュールレジストリサービス間通信の管理各モジュール（8001〜8010）を動的に登録・ヘルスチェック。ポータルからすべてのモジュールを統一的に起動・停止・状態確認。
プロキシルーターモジュール間通信の透過的転送ポータルから /proxy/{module_key}/ で各モジュール UI へアクセス。認証トークンをヘッダーに付与して転送。

📜 patent_search :8004 特許検索・IPC→ECCN/FEFTA マッピング・特許↔学術論文双方向リンク
機能名目的説明
特許検索（BigQuery / Lens.org）競合・先行技術の体系的調査BigQuery に接続された Lens.org 全特許データベースからキーワード・出願人・発明者・IPC 分類コード・出願年範囲で検索。1 億件超の特許に対して SQL クエリで高速検索。
J-PlatPat フォールバックBigQuery 未設定時の代替検索BigQuery が設定されていない場合は自動的に J-PlatPat API（INPIT 公式）にフォールバック。簡易キーワード・発明者・出願人検索に対応。DNS エラーも graceful に処理。
検索ソース表示データ出所の明示検索結果に source: "bigquery" または source: "jplatpat" フィールドを付与して、どのデータソースを使用したかを明示。
IPC → ECCN/FEFTA マッピング特許の輸出管理分類の自動推定IPC 分類コードから EAR/ECCN または外為法（FEFTA）カテゴリへのエッジ 996 件。特許に管理品の該非可能性スコアを自動付与。
特許出願人 制裁リスト一括照合特許技術の利用リスク検知特許の出願人・権利者名を screening モジュールに照合し、制裁対象組織の特許技術を取引・ライセンスに使用する際のリスクを事前検知。
特許 → 関連学術論文リンク技術系譜の横断的調査特許番号を指定すると、特許テキストを FAISS Layer B で検索した上で関連する学術論文（Layer D）との双方向リンクを生成。技術の論文→特許→製品の流れを追跡。
論文キーワード → 関連特許検索学術成果の知財展開調査論文のキーワード・要旨テキストを FAISS Layer B（特許チャンク 1,595 件）でセマンティック検索して関連特許を発見。学術論文の技術が特許化されているかを調査。
FAISS Layer B インデックス特許テキストのベクトル検索特許明細書・請求項をチャンク分割した 1,595 ベクトルを E5 モデルでインデックス化。技術説明のセマンティック類似度に基づいて特許群をクラスタリング。
検索ステータス確認接続状態の把握GET /status で BigQuery 接続状態・J-PlatPat フォールバック状態・インデックス件数を確認。
🛡 screening :8005 OFAC SDN / BIS Entity List スクリーニング・月次自動同期
機能名目的説明
OFAC SDN スクリーニング米国財務省制裁対象者の照合OFAC（米国財務省外国資産管理局）の SDN（特別指定国籍者）リストに対して名称ベースで照合。個人・法人・船舶・航空機を対象。
BIS Entity List スクリーニング米国商務省輸出管理対象者の照合BIS（米国商務省産業安全保障局）の Entity List に対して照合。対象者への輸出・再輸出には個別許可証が必要。
類似名称ファジーマッチング名義変更・表記揺れへの対応完全一致だけでなく、スペルの揺れ・略称・漢字表記の差異に対してファジーマッチングを実施。一致スコアとともにヒット候補を返却。
スクリーニング結果詳細ヒット根拠の確認一致した SDN/Entity List のエントリ名・ID・プログラム（対象制裁根拠）・住所・関連エイリアス・一致スコアを構造化して返却。
月次自動同期スケジューラー制裁リストの常時最新化OFAC/BIS の公式サイトから毎月自動でリストをダウンロード・差分更新。新規追加・削除されたエントリを検知して DB を最新状態に維持。
スクリーニング API（内部連携用）他モジュールからの呼び出しplatform-core（与信管理・取引先照合）・ai_validation（取引相手照合）・rnd_assessment（人物照合）から HTTP API で統一的に呼び出し可能。認証トークン付与で内部通信をセキュア化。
スクリーニング履歴管理照合証跡の保存照合実行日時・照合対象・結果（ヒット有無・スコア）をデータベースに記録。監査時に「いつ・誰を・どのリストで照合し・結果がどうだったか」を証明。
🔢 hs_classifier :8006 HS コード AI 分類エンジン（FAISS Layer C 5,476 件）
機能名目的説明
HS コード同期検索（GET /search）即時分類結果の取得品名・仕様テキストを FAISS Layer C（5,476 件）でセマンティック検索し、類似 HS コードと類似度スコアを即時返却。top_k パラメータで取得件数を調整可能。
HS コード同期判定（POST /classify/sync）Webhook 不要の同期 APIai_classification から直接呼び出す同期判定エンドポイント。heading 再ランキングを含む最終推奨 5 件を即時返却。外部 Webhook が不要な内部連携に使用。
HS コード非同期判定（POST /classify）大量品目の非同期バッチ処理判定リクエストを受け付けてバックグラウンドで処理し、完了後に指定 Webhook URL へ結果を POST 通知。ERP 連携や定期バッチでの大量品目処理に対応。
heading（4 桁）単位クラスタリング再ランキング分類精度の向上FAISS 近傍検索の生の結果を HS heading（4 桁）単位でグループ化し、グループ内最高スコアの代表候補のみを残して上位 5 件を再構成。同一見出し内の重複を除去して実用的な候補セットを生成。
日本語 FEFTA ラベル除外検索ノイズの低減Layer C の embed_text から日本語の外為法（FEFTA）ラベルを除外することで、「集積回路」等の日本語クエリに対して無関係な heading（セルロース等）が上位に来るノイズを解消。
HS コード詳細取得（GET /hs/{code}）コード情報の参照HS コードを指定して品目説明・chapter 説明・heading 説明・関連 FEFTA 項番・関連 ECCN（マッピングが存在する場合）を参照。
インデックス状態確認（GET /index/status）システム稼働状況の確認Layer C インデックスのロード状態・ベクトル数・最終更新日時を確認。インデックス再構築後の反映状況の確認に使用。
🤖 DAP（先輩担当者モード） :8010 Claude API ベースの AI アシスタント・全モジュール横断ガイダンス・プロアクティブ警告

FAISS RAG 連携（Layer A）規制条文に基づく根拠ある回答質問テキストを FAISS Layer A で検索して関連する外為法・EAR の規制テキストを取得し、RAG（検索拡張生成）として LLM に提供。「根拠不明な回答」を防止し、規制条文を引用した信頼性の高い回答を生成。
プロアクティブ アラートバナー見落としリスクの自発的通知ページロード時・特定操作後に、ユーザーが見落としがちなリスク（E:1 国への輸出検知・未照合の取引先・期限切れ許可証等）をチャット外のバナーで自発的に通知。
