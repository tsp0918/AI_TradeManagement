ユースケース 1: 新規品目の輸出審査フロー

Use Case 01
EAR 規制品を新規輸出する際の標準審査
半導体・通信機器など EAR 規制対象品を新規輸出する際に、品目登録から審査完了まで一貫して進めるフロー。
👤 輸出管理担当者
品目登録
→
HS 判定
→
AI取引審査
→
制裁照合
→
審査完了
1
品目を登録する ai_classification
サイドバーの 「業務フロー → 品目管理」 を開き、右上の「＋ 新規登録」をクリック。 品目名・型番・メーカー・仕様（技術パラメータ）を入力して保存する。
🗂 業務フロー → 品目管理 → 新規登録
2
HS コードを AI 判定する hs_classifier
品目詳細ページの 「HS コード判定」 ボタンをクリック。 FAISS ベクター検索（5,476件）が上位 5 候補を提示するので、適切なコードを選んで「反映」する。 ECCN は HS コードから自動付与される。
🗂 品目管理 → 品目詳細 → HS コード判定
3
取引先・需要者を制裁照合する screening
「業務フロー → 取引先スクリーニング」 で取引先名（英語）を入力し「一括照合」を実行。 OFAC・BIS-EL・EU・UK 等 7 ソース約 21,000 件と照合する。 結果が MATCH の場合は取引を即時停止しコンプライアンス担当へエスカレーション。
🗂 業務フロー → 取引先スクリーニング → 一括照合
4
AI取引審査を実行する ai_validation
「業務フロー → AI取引審査 → 新規審査」 で取引を作成。 品名・ECCN・仕向地・需要者・用途を入力して審査開始。 FAISS Layer A/B（外為法・EAR・ITAR・EU 等 2,999 ベクトル）による 2 リスト照合、 EAR Country Chart リスク評価、ライセンス例外チェックが自動実行される。
判定結果: CLEAR / REVIEW / REQUIRES_PERMIT
🗂 業務フロー → AI取引審査 → 新規審査
5
判定結果を確認・証跡保存する
取引詳細ページに審査根拠（照合テーブル・EAR Section 4 キャッチオールレポート）が記録される。 REQUIRES_PERMIT の場合は次の UC6（輸出許可申請ドラフト）へ進む。 結果は自動保存され監査証跡として利用できる。
ECCN が不明な場合: HS コード判定の結果から候補が提示されます。迷う場合は DAP チャットに「ECCN 判定サポート」と入力してください。

ユースケース 2: R&D 起案から品目登録まで

Use Case 02
新規 R&D プロジェクトを起案し、リスク評価後に品目登録する
R&D チームリーダーが新技術のプロジェクトを起案し、AI がリスクスコアリング・開示戦略・セキュリティポスチャを分析。その後、輸出管理担当者が品目登録・AI取引審査へ連携するエンドツーエンドのフロー。
👤 R&D チームリーダー 👤 輸出管理担当者
プロジェクト起案
→
AI リスク評価
→
知財審査
→
品目登録
→
AI取引審査
1
新規プロジェクトを起案する rnd_assessment
「業務フロー → R&D リスク評価 → 新規プロジェクト」 を開き、 プロジェクト名・技術分野・研究フェーズ・エンドユーザー国・パートナー国を入力する。 「使用用途テンプレート」「需要者テンプレート」「開示テンプレート」の 3 つのテンプレートをそれぞれ入力する。
🗂 業務フロー → R&D リスク評価 → 新規プロジェクト
2
AI リスクスコアを確認する
プロジェクト詳細画面に 総合スコア（0〜100）と 4 次元リスク評価が表示される。
• 技術リスク: 軍民両用性・軍事キーワード・再現リスク
• 用途リスク: 研究フェーズ・再移転可能性・仕向地
• 需要者リスク: 制裁照合済みか・エンドユーザー国
• 法規制リスク: 輸出管理感度・軍事隣接性・スクリーニング状態
80点以上: 要停止 / 60〜79点: 法務エスカレーション
3
開示戦略とセキュリティポスチャを確認する
詳細画面の「Explainability」セクションに AI の判断根拠が表示される。
開示戦略: 特許公開 / 営業秘密（秘匿）/ ハイブリッド / 保留
セキュリティポスチャ: 低リスク / 管理対象 / 高感度 / 制限 / 要エスカレーション
根拠はすべて日本語で表示され、知財戦略の意思決定に使用できる。
4
知財審査（IP Review）を完了する
詳細画面下部の「知財審査」フォームに審査結果・エビデンスファイルを添付して保存する。 ワークフロー進捗バーの ④ 知財審査 が完了マーク（✓）に変わる。
5
品目管理へ登録する ai_classification
詳細画面下部の「品目管理への登録」ボタンから品目登録ページへ遷移する。 R&D プロファイルの情報が一部自動引き継ぎされる。 ワークフロー進捗バーの ⑤ 品目登録 が完了に変わる。
🗂 R&D 詳細 → 品目管理への登録
「⑤ 品目登録」が完了したら UC1 の手順 2（HS コード判定）以降に進んでください。

ユースケース 3: サプライヤー申告・調達管理

Use Case 03
海外サプライヤーに原産性申告書を提出させ、BOM を管理する
サプライヤーポータル URL を発行 → サプライヤーが申告書・証明書をアップロード → 自社で BOM ツリーに組み込み De Minimis を計算するフロー。
👤 輸出管理担当者
1
サプライヤー申告を作成する platform-core
「受注後 ERP → 調達・BOM 管理 → ＋ サプライヤー申告」 を開き、 サプライヤー名・品目・対象ノードを入力して保存。 ポータル URL が自動生成される。
🗂 受注後 ERP → 調達・BOM 管理 → サプライヤー申告
2
ポータル URL をサプライヤーへ送付する
申告詳細ページの「ポータル URL」をコピーし、メール等でサプライヤーへ送付する。 サプライヤーはこの URL から申告書・証明書（PDF 等）をアップロードできる。
🗂 サプライヤー申告 → ポータル URL コピー
3
提出済み書類を確認・ダウンロードする
申告詳細ページの「提出書類」タブにアップロードされたファイルが一覧表示される。 各ファイルのリンクからダウンロードできる。申告ステータス（pending / submitted / approved）を更新して管理する。
4
BOM ツリーと De Minimis を確認する
「受注後 ERP → 調達・BOM 管理」 でサプライチェーンノードを登録し BOM ツリーを構築。 De Minimis 計算（米国原産成分の価値比率）が自動算出される。 De Minimis が 25% を超えるノードには 要注意 が表示される。
🗂 受注後 ERP → 調達・BOM 管理 → BOM ツリー
サプライヤーポータルへのメール自動送信は現在未実装です。URL のコピー・手動メール送付で対応してください。

ユースケース 4: 取引先デューデリジェンス

Use Case 04
新規取引先の制裁・財務リスクを総合評価する
取引開始前に制裁リスト照合・財務スコア・統合コンプライアンススコアを確認し、取引可否判断の根拠を記録するフロー。
👤 輸出管理担当者
1
制裁リストを一括照合する screening
「業務フロー → 取引先スクリーニング → 一括照合」 で取引先名（英語・現地語）を入力。 OFAC SDN / BIS-EL / BIS-UVL / BIS-MEU / BIS-DPL / EU / UK の 7 ソースを同時照合。 照合結果に一致スコア・ソース・エンティティ詳細が表示される。
🗂 業務フロー → 取引先スクリーニング → 一括照合
2
与信・統合スコアを確認する platform-core
「専門ツール → 与信管理」 で取引先を検索し、財務スコア・制裁統合スコア・ リスク評価コメントを確認する。スコアは制裁照合結果と財務指標を統合したコンポジットスコア。
🗂 専門ツール → 与信管理
3
コンプライアンス進捗に取引先を記録する
「受注後 ERP → コンプライアンス進捗」 の該当案件に DD 完了を記録する。 7 ステージパイプライン（起案→品目照合→制裁照合→許可申請→発送→記録→クローズ）の 進捗が可視化される。証跡として審査日時・担当者・結果が保存される。
🗂 受注後 ERP → コンプライアンス進捗
スクリーニング結果が MATCH の場合: 取引を即時停止し、法務・コンプライアンス担当へエスカレーションしてください。一致エンティティの詳細（ソース・エイリアス）を証跡として保存することを忘れないでください。

ユースケース 5: みなし輸出審査・管理

Use Case 05
外国籍研究者・技術者への技術提供（みなし輸出）を審査する
外国籍の研究員・技術者が社内で規制技術にアクセスする場合の「みなし輸出」申請フロー。人物スクリーニング → リスク評価 → 台帳記録までを一元管理する。
👤 輸出管理担当者 👤 人事・研究管理
1
人物スクリーニングを実行する rnd_assessment
「業務フロー → R&D リスク評価 → 人物管理」 から対象者の情報（氏名・国籍・所属・役職）を登録し スクリーニングを実行する。制裁リストとの照合結果が表示される。
🗂 業務フロー → R&D リスク評価 → 人物管理
2
みなし輸出申請を作成する
「業務フロー → 役務取引管理 → みなし輸出申請」 を開き、 対象者・提供技術・アクセス期間・目的を入力して申請を作成する。 R&D プロジェクトとリンクさせると該非判定情報を自動引き継ぎできる。
🗂 業務フロー → 役務取引管理 → みなし輸出申請
3
経済安保法チェックを実施する rnd_assessment
「専門ツール → 経済安保法チェック」 で特許非公開リスクスコアと ICP（内部管理プログラム）自己診断（CISTEC 8 要素）を確認する。 経済安保法の指定技術に該当する場合は追加の申請が必要になる可能性がある。
🗂 専門ツール → 経済安保法チェック
4
みなし輸出台帳に記録する
申請が承認されたら台帳に記録する。外為法上 7 年間の保存義務がある（CISTEC 様式に対応）。 台帳は 「業務フロー → 役務取引管理 → みなし輸出台帳」 で一覧確認できる。
🗂 業務フロー → 役務取引管理 → みなし輸出台帳
外国籍の研究者が規制技術にアクセスする場合は、たとえ国内の研究室内であっても外為法上の「みなし輸出」に該当する場合があります。事前審査を忘れずに実施してください。

ユースケース 6: 輸出許可申請ドラフト生成

Use Case 06
REQUIRES_PERMIT 判定後に許可申請ドラフトを自動生成する
AI取引審査で許可申請が必要と判定された取引に対し、申請書ドラフトを自動生成し、許可証の価値消費・期限管理まで行うフロー。
👤 輸出管理担当者
1
取引詳細から申請書ドラフトを生成する ai_validation
REQUIRES_PERMIT と判定された取引の詳細ページ下部にある 「輸出許可申請ドラフト生成」 ボタンをクリック。 取引情報から申請書の基本項目が自動入力される。
🗂 業務フロー → AI取引審査 → 取引詳細 → 輸出許可申請ドラフト生成
2
許可証を登録する platform-core
「受注後 ERP → 輸出許可申請」 で申請を管理する。 許可証番号は EL-{TYPE}-{YEAR}-{SEQ:04d} 形式で自動採番される。 許可有効期限・許可総額を入力して保存する。
🗂 受注後 ERP → 輸出許可申請 → 新規申請
3
出荷ごとに価値を消費する
出荷のたびに許可証詳細ページの 「価値控除」 フォームから出荷金額を入力する。 残存許可額がカラーバーで視覚表示される（残量 20% 未満: 要注意 / 期限 30 日以内: 期限切れ警告）。
🗂 受注後 ERP → 輸出許可申請 → 許可証詳細 → 価値控除
4
期限アラートを確認する
期限が近い許可証はスケジューラーが自動検出し、案件ダッシュボードのアラートとして表示される。 「管理 → 案件ダッシュボード」 を定期的に確認して期限切れを防ぐ。
🗂 管理 → 案件ダッシュボード → 規制動向アラート

ユースケース 7: BOM + De Minimis 計算

Use Case 07
製品の BOM を管理し米国原産比率（De Minimis）を計算する
EAR の De Minimis ルールに基づき、製品に占める米国原産成分の価値比率を算出して再輸出規制の適用可否を判断するフロー。
👤 輸出管理担当者
1
サプライチェーンノードを登録する platform-core
「受注後 ERP → 調達・BOM 管理 → ＋ ノード追加」 で部品・素材を登録する。 各ノードに原産国・仕入れ価格・米国原産成分（USD）を入力する。
🗂 受注後 ERP → 調達・BOM 管理 → ノード追加
2
BOM ツリーを構築する
各ノードの親子関係（親品目 UUID）を設定して BOM ツリーを構築する。 品目管理の plat_item UUID と紐づけて品目マスタとも連携できる。
3
De Minimis 比率を確認する
BOM ツリー画面で製品全体の De Minimis 比率が自動算出される。 25% 超（管理対象国向け） / 10% 超（テロ支援国向け） の場合は EAR 規制が外国製品にも適用される（FDP ルール）。 De Minimis 比率は証跡として出力できる。
De Minimis 閾値は仕向地によって異なります（一般的な規制対象国: 25%、テロ支援国: 10%）。仕向地の EAR Country Chart 区分は AI取引審査モジュールで確認できます。

ユースケース 8: EPA/FTA 特恵税率照会

Use Case 08
HS コードと仕向地から EPA/FTA 特恵税率を調べる
日本が締結している FTA 協定（JAEPA・RCEP・CPTPP 等）のうち、特定の HS コード・仕向地に適用できる特恵税率を照会するフロー。
👤 輸出管理担当者 👤 貿易部門
1
特恵税率照会フォームを開く platform-core
「受注後 ERP → EPA/FTA 特恵税率」 を開く。
🗂 受注後 ERP → EPA/FTA 特恵税率
2
HS コードと仕向地を入力して照会する
HS コード（例: 8542.31）と仕向地国（例: AU = オーストラリア）を入力して「照会」をクリック。 適用可能な FTA 協定と特恵税率・一般税率・削減スケジュールが一覧表示される。
3
協定一覧で対象協定を確認する
画面下部の「協定一覧」タブで日本が締結している 10 協定 （JAEPA / RCEP / CPTPP / 英日 EPA / 日米貿易 / ASEAN 各国）の概要を確認できる。 原産地証明書の必要有無も確認すること。
現在のデータは代表 HS コード（8 種類）のサンプルデータです。実務では品目単位のフルデータが必要です。HS コードが見つからない場合は通常税率で計算してください。

ユースケース 9: 技術インテリジェンス・特許調査

Use Case 09
競合技術・特許を調査し制裁リストと照合する
BigQuery / J-PlatPat を使った特許検索、Semantic Scholar / Lens.org 学術論文の取得、制裁リストとの照合、R&D プロジェクトとの双方向リンクを管理するフロー。
👤 R&D チームリーダー 👤 知財担当者
1
特許検索を実行する patent_search
「専門ツール → 特許検索」 でキーワード・CPC 分類・出願人・年代を入力して検索。 BigQuery（公開特許 DB）を優先し、フォールバックで J-PlatPat を使用する。 検索結果に発明者・出願人・要約が表示される。
🗂 専門ツール → 特許検索
2
発明者・出願人を制裁リストで照合する
検索結果の各特許に「制裁照合」ボタンが表示される。クリックすると発明者・出願人名を スクリーニングモジュールへ送り、OFAC 等との照合結果を表示する。 MATCH の場合は技術移転・共同研究のリスクを精査する。
3
学術論文インテリジェンスを確認する rnd_assessment
「業務フロー → R&D リスク評価 → 技術インテリジェンス」 で関連技術分野の 学術論文（Semantic Scholar / Lens.org 収集済み）・Layer D FAISS（高次元技術ベクトル）の 類似度スコアを確認する。競合技術の動向把握に使用する。

ユースケース 10: 仕様変更後のコンプライアンス再審査

Use Case 10
品目の仕様変更後に影響評価と AI 再判定を実行する
製品の性能・仕様が変更された際に、品目バージョンを更新し、旧バージョンとの差分を確認し、AI取引審査を再実行するフロー。
👤 輸出管理担当者
1
新バージョンを作成する platform-core
「受注後 ERP → 品目バージョン管理」 で対象品目を選択し「新バージョン作成」をクリック。 変更内容（仕様変更箇所・変更理由）を入力して保存する。
🗂 受注後 ERP → 品目バージョン管理 → 新バージョン作成
2
バージョン差分と影響アセスメントを確認する
バージョン詳細ページの「差分比較」タブで旧バージョンとの変更点が色分け表示される。 「影響アセスメント」では変更がコンプライアンス上重大な変化（ECCN 区分変更の可能性等）か AI が評価してコメントを提示する。
3
AI 再判定を実行する
バージョン詳細ページの 「AI 再判定」 ボタンをクリックすると ai_validation モジュールへ新バージョンの仕様で再審査リクエストが送られる。 旧バージョンの判定結果との比較が同一ページで確認できる。
🗂 受注後 ERP → 品目バージョン管理 → バージョン詳細 → AI 再判定
4
規制レジームを一括照合する platform-core

🗂 専門ツール → 規制レジーム照合
仕様変更後に ECCN が変わる可能性があります。特に性能パラメータ（処理速度・暗号強度・精度等）が EAR の技術パラメータ閾値を超えた場合は、必ず規制レジーム照合を再実行してください。

よくある質問（FAQ）

基本操作

どのモジュールから始めればいいですか？
新規品目の輸出審査なら「品目管理」から始めてください（UC1 参照）。R&D プロジェクトが起点なら「R&D リスク評価」から始めます（UC2 参照）。取引先の事前確認が目的なら「取引先スクリーニング」を最初に実行してください（UC4 参照）。
サイドバーに表示されない機能があります。
ポータル（app.tsp-aitrademanagement.com）のサイドバーを確認してください。サイドバーは「業務フロー」「受注後 ERP」「専門ツール」「管理」の 4 セクションに分かれています。モジュールが起動していない場合はプラットフォーム管理（管理 → プラットフォーム管理）でサービス状態を確認してください。
DAP チャットはどこにありますか？
全モジュールの画面右下に「DAP チャット」ウィジェットが表示されています。クリックするとチャットパネルが開きます。「このページの使い方を教えて」「○○はどこでできますか？」など自然言語で質問できます。
データを CSV でエクスポートできますか？
品目管理・スクリーニング結果などの一覧ページに CSV エクスポートボタンが表示されています。取引詳細・審査レポートは各詳細ページの「エクスポート」または「印刷」機能を使用してください。
ブラウザの「戻る」ボタンが効きません。
現在のアーキテクチャでは各モジュールが iframe 内に表示されるため、ブラウザのバック機能が正常に動作しない場合があります。モジュール内のナビゲーション（「← 一覧に戻る」等のリンク）を使用してください。

判定結果の見方

AI取引審査の CLEAR / REVIEW / REQUIRES_PERMIT はどういう意味ですか？
CLEAR: 規制リストに明確な一致なし。輸出許可不要と判断できる可能性が高い（最終判断は担当者が行ってください）。REVIEW: 部分一致または要注意フラグあり。担当者による追加確認が必要。REQUIRES_PERMIT: 許可申請が必要と判定。UC6 の手順に従い輸出許可申請ドラフトを作成してください。
R&D リスクスコアの 4 次元はそれぞれ何を評価していますか？
技術リスク（35%ウェイト）: 軍民両用性・軍事キーワード・再現リスクを評価。用途リスク（25%）: 開発フェーズ・再移転可能性・仕向地リスクを評価。需要者リスク（25%）: エンドユーザー国のリスク区分・制裁照合済みかを評価。法規制リスク（15%）: 輸出管理感度・軍事隣接性・スクリーニング状態を独立次元として評価。総合スコアはこれら 4 次元の加重平均です。
スクリーニング結果の「一致スコア」はどう解釈しますか？
一致スコア 100% は完全一致（同名エンティティ）、80%以上は高い確信度での一致です。80% 未満の場合は名前の類似度によるファジーマッチです。スコアに関わらず MATCH 判定が出た場合は必ず担当者がエンティティ詳細（住所・別名・国籍等）を確認して最終判断してください。
HS コード判定の「類似スコア」が低い場合はどうすれば良いですか？
上位 5 候補の類似スコアがすべて低い（60% 未満）場合は、品目説明文を英語で入力し直すか、技術パラメータを詳細に記述してみてください。それでも適切な候補が出ない場合は、関税協会の HS コード分類相談（外部）か DAP チャットで相談してください。
EAR Country Chart の「AT」「NS2」等の区分は何ですか？
EAR Country Chart（15 CFR Supplement No.1 to Part 738）の規制理由コードです。AT: 反テロ（Anti-Terrorism）、NS: 国家安全保障（National Security）、NP: 核不拡散（Nonproliferation）、MT: ミサイル技術（Missile Technology）等があります。各 ECCN の規制理由コードが仕向地の Country Chart と交差する場合に許可が必要になります。詳細は DAP チャットで確認できます。
De Minimis が 25% を超えた場合、何をすればいいですか？
一般的な規制対象国向けの場合、米国原産成分が 25% を超える外国製品には EAR が適用されます（Foreign-Produced Direct Product Rule）。AI取引審査で当該製品を改めて審査し、REQUIRES_PERMIT と判定された場合は輸出許可申請が必要です。テロ支援国（KP・IR・SY等）向けは 10% が閾値になります。

エラー・トラブル対応

モジュールの画面が「接続できません」と表示されます。
対象モジュールのサービスが停止している可能性があります。IT 管理者に連絡し「管理 → プラットフォーム管理」でモジュールの起動状態を確認してもらってください。緊急の場合は ./start.sh でサービスを再起動してください。
FAISS 照合で「ベクターインデックスが見つかりません」エラーが出ます。
FAISS インデックスファイルが未ビルドの可能性があります。IT 管理者に python scripts/build_layer_*.py でインデックスを再ビルドしてもらってください。通常、サービス起動時に自動ロードされます。
特許検索で「BigQuery に接続できません」エラーが出ます。
BigQuery 認証トークンの期限切れか、ネットワーク障害の可能性があります。フォールバックとして J-PlatPat 経由の検索に自動切り替えされます。BigQuery が長期間使えない場合は IT 管理者に GCP 認証情報の更新を依頼してください。
スクリーニング照合が完了しない（ローディングが続く）。
一括照合で入力名が多い場合、処理に時間がかかることがあります（目安: 10 件で約 5〜10 秒）。30 秒以上経過する場合はページをリロードして再実行してください。それでも解決しない場合は DAP チャットで状況を報告してください。
R&D リスクスコアが常に低く（25 点前後）計算されます。
3 つのテンプレート（使用用途・需要者・開示）の入力が不十分な可能性があります。特に「エンドユーザー国」「軍事エンドユーズの可能性」「輸出管理感度」フィールドが未入力だとスコアが低く算出されます。テンプレートの必須フィールドを確認して入力し直してください。

法令・規制 Q&A

外為法と EAR（米国輸出管理規則）は何が違いますか？
外為法（外国為替及び外国貿易法）は日本の法律で、経済産業省令の「輸出貿易管理令」に基づき規制品目・規制地域を定めています。EARは米国商務省 BIS が管轄する米国の輸出管理規則で、米国原産品や米国技術が組み込まれた外国製品にも適用されます（域外適用）。本プラットフォームはその両方に対応しています。
ECCN がわからない品目はどうすれば良いですか？
まず HS コード判定（専門ツール → HSコード判定）で HS コードを特定し、HS→ECCN マッピングから候補を取得してください。それでも不明な場合は米国メーカーへの CCATS（Commodity Classification Advisory Request）、または経済産業省の安全保障貿易管理課への相談を検討してください。自信がない場合は DAP チャットで「ECCN の調べ方」を聞くと手順をガイドします。
EAR99 の品目は何も審査しなくていいですか？
EAR99 であっても、制裁対象国・制裁対象者への輸出は禁止されています。また、キャッチオール規制（EAR Section 744）により、大量破壊兵器への転用が疑われる場合は EAR99 でも許可が必要になります。必ず制裁スクリーニング（UC4）と Red Flag チェックを実施してください。
許可証なしで輸出できる「ライセンス例外」はどれが使えますか？
主な EAR ライセンス例外: ENC（暗号品目）、TSR（技術・ソフトウェア再輸出）、TMP（一時輸出）、RPL（修理・返却）等があります。AI取引審査モジュールが自動的に適用可能な例外を評価します。例外の適用には要件（仕向地・品目・エンドユーザー条件）を満たす必要があります。詳細は DAP チャットで確認してください。
みなし輸出として審査が必要な技術提供の例は何ですか？
社内での技術提供でも審査が必要な代表例: ①外国籍研究員への規制技術の口頭説明・資料共有、②外国籍技術者が規制品目を操作・テスト、③規制技術が含まれる研究データへのアクセス付与、④外国籍インターンへの技術教育。国籍に関わらず永住権・米国籍を持つ場合は対象外（米国 EAR の場合）。詳細は法務・コンプライアンス担当に確認してください。
審査記録はどのくらいの期間保存が必要ですか？
外為法では輸出許可申請書・審査記録の 7 年間保存が義務付けられています（外為法施行令）。米国 EAR では 5 年間の記録保持が必要です（15 CFR §762）。本プラットフォームの審査結果・取引詳細はすべてデータベースに保存され、証跡として活用できます。CISTEC 様式での出力にも対応しています。
